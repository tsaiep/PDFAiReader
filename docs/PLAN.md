# AI PDF Reader — 專案開發計劃書

**版本：** v1.0  
**目標平台：** macOS  
**專案類型：** 本機桌面應用程式  
**核心技術：** SwiftUI / PDFKit / Apple Vision / Codex CLI / SQLite  
**開發方式：** AI-assisted development（Codex）

---

## 一、專案概述

### 1.1 專案目標

開發一套專為外文電子書、掃描書籍與 PDF 文件設計的 macOS 閱讀器。

提供一般 PDF 閱讀器應有的瀏覽、縮放、搜尋、書籤、註記及閱讀進度管理，同時整合 Codex CLI，實現 AI 翻譯。

使用者可以選擇翻譯整份文件，也可以在閱讀過程中自動翻譯當前頁面及接下來指定數量的頁面，減少等待時間及重複運算。

### 1.2 設計原則

1. **閱讀體驗優先：** 即使 AI 翻譯不可用，仍是一套完整的 PDF 閱讀器。
2. **原始文件不變：** 不修改原始掃描圖像，所有 OCR、翻譯與註記獨立儲存。
3. **按需處理：** 不要求開啟文件後立即完成全書 OCR 或翻譯。
4. **可中斷、可恢復：** 翻譯過程中可關閉文件、暫停任務，重新開啟後延續進度。
5. **模型可選：** 使用者自行選擇可用 Codex 模型，不將翻譯服務綁定單一模型。
6. **結果可重用：** 已完成的辨識與翻譯儲存至本機，避免重複消耗額度。
7. **模組化：** OCR、翻譯、閱讀器 UI 與資料儲存彼此獨立，便於後續更換模型或功能擴充。

掃描 PDF 的影像顯示不因介面深色模式而自動反相，避免破壞插圖或攝影作品的原貌。

### 2.2 OCR 文字辨識

**主要目標：對純圖片掃描 PDF 建立可選取、可搜尋、可翻譯的文字結構。**

處理流程：

1. 開啟 PDF 後，先檢查頁面是否存在可用的文字層。
2. 若有文字層，直接提取並進行品質檢查。
3. 若文字層不存在或內容品質不佳，將頁面渲染為影像，交由 Apple Vision 辨識。
4. 儲存文字內容、行／段落位置、辨識信心度及頁碼。
5. 根據版面資訊重建閱讀順序，處理多欄排版、標題、註腳、圖片說明。
6. 將辨識文字與原頁面座標建立關聯，支援文字選取、搜尋與段落定位。

**辨識策略**

- 預設使用 Apple Vision 的 Accurate 模式。
- 支援英文、中文及其他系統 OCR 支援的語言。
- 保留原始 OCR 結果，不直接用 AI 改寫覆蓋。
- OCR 品質過低時標記為待確認，可對單頁重新辨識。
- 支援使用者手動修正錯字。
- OCR 結果與翻譯結果分開儲存。
- 預設使用本機 OCR，不上傳整張書頁。

**重要：** OCR 的文字順序不一定等於實際閱讀順序，必須設計獨立的 Layout Analysis 模組。特別是藝術書、雜誌、攝影集常見的多欄、跨欄與不規則排版。

### 2.3 AI 翻譯功能

#### A. 單段翻譯

- 使用者選取文字後，顯示浮動翻譯視窗。
- 支援複製原文、複製譯文與重新翻譯。
- 翻譯結果可加入筆記。
- 可手動選取其他翻譯模型重試。

#### B. 當前頁翻譯

- 翻譯使用者正在閱讀的頁面。
- 依照辨識出的段落順序處理。
- 保留標題、內文、圖片說明等結構。
- 不將 AI 解說混入一般翻譯內容。

#### C. 閱讀預翻譯

使用者可設定「當前可見頁面 + N 頁」。

例如：

- 當前可見頁：第 20 頁
- 預翻頁數：5 頁
- 目標處理範圍：第 20–25 頁

若目前為雙頁模式，第 20、21 頁同時可見，則以可見集合為基礎，處理第 20–26 頁，即可見兩頁加上後續五頁。

功能需求：

- N 可調整，預設為 5。
- 可關閉自動預翻譯。
- 翻頁後重新計算任務優先順序。
- 已完成翻譯不重複執行。
- 正在翻譯的任務不因輕微捲動反覆重啟。
- 使用者跳至較遠頁數時，新可見頁面優先處理。
- 可設定預翻譯只在閱讀器開啟時運作。

#### D. 整份翻譯

- 將全書所有頁面加入背景翻譯佇列。
- 顯示完成頁數、失敗頁數與目前處理頁數。
- 可暫停、繼續、取消。
- 已完成的翻譯持續寫入資料庫。
- 重新開啟程式後可從未完成的頁面繼續。
- 可設定翻譯範圍，例如第 30–100 頁。
- 閱讀與整書翻譯可同時進行，但閱讀相關任務享有較高優先級。

### 2.4 翻譯顯示方式

第一版以以下模式為主：

**模式 1：原文閱讀**

完整呈現原始 PDF，使用者可選取文字查看翻譯。

**模式 2：左右對照**

原始 PDF 與譯文並排顯示。右側以標題、段落及圖片說明分區呈現。

- 支援調整左右面板比例。
- 支援點選譯文定位原文。
- 捲動或翻頁時同步對應頁數。
- 尚未翻譯完成時顯示原文與處理狀態。

**模式 3：翻譯閱讀**

主要顯示已翻譯的文字，並保留查看原始頁面的入口。

此模式不要求完全重建原書版面。

**後續擴充：原位翻譯**

在原始掃描頁面上覆蓋翻譯文字，盡可能保持圖片與排版。

由於中文與英文的字數、換行及字型尺寸不同，此功能需另外開發排版引擎，不納入第一版必要需求。

## 三、Codex CLI 翻譯引擎

### 3.1 整合方式

使用 Codex CLI 的非互動模式 `codex exec` 作為翻譯執行介面。

主程式透過 Process 啟動本機 CLI 程序，將待翻譯資料及指令送入 Codex，讀取結構化結果，再存入本機資料庫。

不透過模擬 GUI 操作 ChatGPT，也不依賴系統剪貼簿。

### 3.2 模型選擇

設定畫面提供：

- Codex CLI 登入狀態。
- 可用模型清單。
- 預設翻譯模型。
- 翻譯品質設定。
- 模型測試功能。
- 自動／手動重新翻譯選項。

模型名稱不得寫死在 UI 中。

模型清單應從 CLI 可取得的模型資訊及使用者設定產生，並驗證模型是否實際可用。

允許保存自訂模型 ID；無法取得完整清單時，提供手動輸入作為備援。

### 3.3 翻譯指令

系統內建預設翻譯 Prompt，另提供進階使用者可編輯的自訂翻譯規則。

預設規則：

1. 翻譯成自然、準確的繁體中文，採用台灣常見用語。
2. 優先維持原文語意、論證結構與敘事語氣。
3. 正確保留藝術、設計、哲學、攝影及技術領域專有名詞。
4. 段落及標題結構應與原文對應。
5. 不任意摘要、補充背景知識或修改作者立場。
6. OCR 疑似錯字不可在無證據下臆測補全。
7. 回傳指定格式的 JSON，不輸出多餘說明。

每個翻譯區塊都應具有穩定 ID，以供後續資料定位。

### 3.4 翻譯上下文

翻譯時除了待翻譯段落，也可以提供有限上下文：

- 前一頁最後數個段落。
- 當前章節標題。
- 書籍名稱、作者或使用者提供的背景。
- 已建立的專有名詞對照表。

上下文只用於理解語意，不能重複輸出到翻譯結果。

每次請求應有明確的輸入範圍，避免隨閱讀頁數增加而無限累積上下文。

### 3.5 任務執行安全性

- 僅允許程式執行預先定義的 Codex 命令。
- 將 OCR 文字視為不可信資料，不允許書本內容覆蓋系統翻譯指令。
- 優先使用唯讀 Sandbox。
- 不允許翻譯 Agent 任意修改本機文件。
- 不執行 PDF 內含的外部命令或提示。
- 記錄任務結果、執行狀態及必要錯誤資訊。
- CLI 不存在、未登入或超出額度時，閱讀器本身仍正常運作。

## 四、翻譯任務排程系統

### 4.1 任務優先級

| 優先級 | 任務 | 說明 |
|---|---|---|
| P0 | 使用者選取段落 | 即時操作，最高優先 |
| P1 | 目前可見頁面 | 優先完成正在閱讀的內容 |
| P2 | 預翻譯頁面 | 當前頁後續 N 頁 |
| P3 | 整書翻譯 | 低優先級背景處理 |

排程器應允許高優先級任務插隊。

已執行的 CLI 工作可依情況完成目前批次，再切換到高優先級任務；遇到明顯過長或無法回應的任務，可以取消並重新排程。

### 4.2 任務狀態

每項翻譯工作至少具有以下狀態：

- Pending：等待執行
- Running：處理中
- Completed：已完成
- Failed：失敗
- Cancelled：已取消
- Stale：來源或設定變更，快取需更新

每個任務記錄重試次數、模型、建立時間、完成時間及錯誤原因。

### 4.3 批次策略

翻譯單位以「段落群組」為主，而不是直接將整本書交給同一個長時間 CLI 工作。

預設可將同一頁的多個段落合併為一批；非常長的頁面則依長度切分。

批次之間必須保留跨頁語境，但不能讓上下文隨任務進度無限制增長。

同時執行的 CLI 翻譯任務數量預設為 1，後續可依穩定度與額度狀況開放調整。

### 4.4 快取與失效規則

翻譯快取需包含：

- 文件識別碼
- 頁碼及段落 ID
- 原始 OCR 文字雜湊
- 目標語言
- 翻譯模型
- Prompt 版本
- 上下文／術語表版本
- 翻譯結果

相同內容及設定不重複執行。

更換模型或翻譯規則後，可選擇使用現有譯文，或針對所選範圍重新翻譯。

## 五、閱讀器架構

### 5.1 技術選型

| 系統模組 | 技術 |
|---|---|
| 桌面 UI | SwiftUI + AppKit |
| PDF 渲染 | PDFKit |
| OCR | Apple Vision |
| 版面分析 | 自訂 Layout Analyzer |
| 翻譯執行 | Codex CLI |
| CLI 事件處理 | Swift Process + JSONL Parser |
| 資料儲存 | SQLite |
| 任務排程 | Swift Concurrency / Actor |
| EPUB 支援 | 後續另選 EPUB 渲染引擎 |
| 檔案系統 | macOS 原生文件存取 API |

### 5.2 系統資料流程

```text
PDF Document
     |
     v
Document Loader
     |
     v
PDFKit Renderer
     |
     +-------> PDF Viewer UI
     |
     v
Text Layer Detector
     |
     +-- Existing Text Layer
     |
     +-- Apple Vision OCR
     |
     v
Layout Analyzer
     |
     v
Structured Text Blocks
     |
     +-------> Search / Selection
     |
     v
Translation Scheduler
     |
     +-- Current Page
     +-- Prefetch N Pages
     +-- Full Document
     +-- Selected Text
     |
     v
Codex CLI Adapter
     |
     v
Translation Result Validator
     |
     v
SQLite Cache
     |
     v
Translation Viewer UI
```

### 5.3 模組職責

**Document Manager**

處理開啟、切換、關閉文件，維護文件識別碼、Metadata 與閱讀進度。

**PDF Renderer**

負責頁面顯示、縮放、連續／雙頁模式與頁面座標轉換。

**OCR Service**

提取文字、辨識掃描頁面及提供辨識範圍。需支援延遲執行及結果快取。

**Layout Analyzer**

將 OCR 行整理為標題、段落、註腳與圖片說明，建立跨頁閱讀順序。

**Translation Scheduler**

根據閱讀位置、使用者動作及整書翻譯狀態產生工作佇列。

**Codex Adapter**

負責模型設定、程序生命週期、輸入資料、結果擷取、取消、逾時及失敗處理。

**Translation Store**

持久化 OCR、翻譯、狀態、書籤、閱讀歷史及相關設定。

**Reader Interface**

管理原文閱讀、左右對照、翻譯面板、進度顯示、快捷鍵與使用者操作。

## 六、資料設計

建議使用 SQLite，至少建立以下資料結構：

| Table | 用途 |
|---|---|
| documents | 文件 ID、路徑、檔案雜湊、Metadata |
| pages | 頁碼、尺寸、OCR 狀態 |
| text_blocks | OCR 原文、區塊座標、閱讀順序 |
| translations | 譯文、模型及翻譯設定版本 |
| translation_jobs | 工作佇列、狀態、錯誤及重試資訊 |
| bookmarks | 書籤及閱讀位置 |
| annotations | 螢光筆、註記及文字備註 |
| reading_progress | 每份書的閱讀進度 |
| preferences | 全域及單書設定 |
| glossary | 專有名詞對照 |

使用文件內容雜湊或其他穩定識別方式避免因重新命名文件而遺失翻譯資料。

資料表需保留遷移版本，方便後續升級。

## 八、開發階段

### Phase 1：PDF 閱讀器基礎

**目標：先完成可獨立使用的閱讀器。**

工作：

- 建立 macOS App 專案
- 整合 PDFKit
- 實作檔案開啟、翻頁及縮放
- 完成單頁、雙頁、連續閱讀模式
- 實作縮圖、基本書籤及閱讀進度
- 建立 SQLite 資料儲存層

**驗收：** 不依賴任何 AI 功能，能穩定閱讀大型掃描 PDF。

### Phase 2：OCR 與文字結構

工作：

- 判斷 PDF 文字層
- 整合 Vision OCR
- 建立 OCR 快取
- 支援選取與搜尋 OCR 文字
- 實作基礎段落重建
- OCR 原文與頁面位置對應

**驗收：** 純圖片掃描 PDF 可以提取、選取及搜尋文字；基本雙欄頁面能維持合理的閱讀順序。

### Phase 3：Codex CLI 翻譯

工作：

- CLI 路徑及登入檢查
- 模型選擇與測試
- 單段／單頁翻譯
- JSON Schema 結果驗證
- 翻譯快取
- 左右對照 UI

**驗收：** 選取段落或頁面後，能正確取得繁體中文翻譯，並於重新開啟文件後保留結果。

### Phase 4：預翻譯與整書任務

工作：

- 任務優先級
- 當前頁 + N 頁預翻譯
- 整書背景翻譯
- 暫停、取消、恢復
- 進度與失敗重試
- 快速翻頁時任務重排
- 任務持久化

**驗收：** 能從一本書的中間開始閱讀，優先翻譯當前頁及後續頁面，同時進行整書翻譯；關閉程式後仍保留進度。

### Phase 5：完整閱讀體驗

工作：

- 目錄及註記
- 搜尋結果導覽
- 原文與譯文同步定位
- 閱讀模式與快捷鍵
- 匯出翻譯及筆記
- 大型文件效能最佳化
- 系統錯誤處理與 UI 完善

**驗收：** 達到可長期使用的閱讀體驗，而非僅能展示翻譯的原型。

## 九、技術風險與對策

### 9.1 OCR 與 macOS 預覽結果可能不同

預覽程式支援 Live Text，不代表 PDF 本身具有可提取的文字層，也不代表自製閱讀器會自動擁有相同的選取行為。

**對策：** 使用 Apple Vision 主動 OCR，建立自己的文字與座標資料結構，不依賴預覽程式內部功能。

### 9.2 複雜排版造成閱讀順序錯亂

多欄、跨頁、腳註與圖片說明可能導致翻譯順序錯誤。

**對策：** OCR、版面分析、翻譯三者分離。保留文字座標和區塊 ID，允許未來重新建構閱讀順序而不重新 OCR。

### 9.3 Codex CLI 翻譯延遲與額度

Codex CLI 是 Agent 執行介面，並非專門為低延遲大量翻譯而設計。不同模型、任務長度與帳戶限制都會影響處理效率。

**對策：**

- 採用有界批次翻譯
- 預翻譯與快取
- 控制並行數量
- 降低無必要的工具操作
- 遇到限制時暫停並保留進度
- 將 Codex 整合封裝成可替換模組

必須在開發初期實測實際額度消耗、延遲與可執行批次大小，不預設訂閱制提供無限制翻譯。

### 9.4 長篇書籍翻譯一致性

分批翻譯可能產生人名、技術術語和語氣不一致。

**對策：** 建立 Glossary、章節背景及一致性規則，並允許使用者修改術語表後選擇性重新翻譯。

### 9.5 原始頁面與譯文對不上

OCR 行與翻譯段落可能不是一對一的關係。

**對策：** 以文字區塊 ID 連結原文與譯文，保留群組對應關係，不要求逐字定位。

## 十、驗收測試

至少準備以下測試文件：

1. 純圖片掃描 PDF（英文單欄）。
2. 雙欄藝術書或雜誌。
3. 圖片與文字混排的設計書。
4. 已有 OCR 文字層的 PDF。
5. 超過 300 頁的大型 PDF。
6. 含跨頁段落、註腳與不規則排版的 PDF。

**核心驗收條件：**

- 開啟大型 PDF 時不必等待全書 OCR。
- OCR 與翻譯不阻塞主畫面的翻頁、縮放及捲動。
- 預翻譯會依照當前可見頁面更新優先級。
- 同一設定下不會重複翻譯已完成的段落。
- 整書翻譯可中斷並恢復。
- 更換翻譯模型不影響原始 OCR 資料。
- CLI 翻譯失敗不造成閱讀器崩潰。
- 文件、快取與註記在重啟後仍可正確載入。
- 修改或移動原始 PDF 時有明確的資料重新連結與失效處理。

## 十二、最終產品定位

本專案不是單純的 PDF 翻譯工具，而是以完整閱讀器為核心，結合 OCR 與可持續處理翻譯任務的 AI 閱讀環境。

核心體驗應是：

**開啟一本掃描書 → 立即開始閱讀 → 自動辨識文字 → 當前及後續頁面自動翻譯 → 在不打斷閱讀的情況下持續提供譯文。**

整書翻譯與模型選擇是此系統的重要能力，但不應犧牲一般閱讀器的穩定性與流暢度。

第一版優先完成原生 PDF 閱讀、掃描 OCR、Codex 翻譯、對照閱讀，以及具備快取和恢復能力的預翻譯排程系統。
